# LilaShift 2.0 · 智能能力过滤、历史变更识别与精准恢复设计

状态：设计草案，**未实现**。本文件只用于开发分支；旧版 Release/IPA 不变。

## 目标
不让普通用户理解 MG/CacheData/CacheExtra 即可安全操作：读取设备 → 检查出厂硬件支持与系统能力 → 识别已有修改 → 排除原生支持项 → 推荐已验证且真正必要的改动 → 预览与备份 → 写入/校验 → 验证 → 可追溯恢复。

## 设备与原生能力分类（每功能独立判断）
- `nativeSupported`：有可信机型+硬件+OS build 证据证明原生支持；**自动跳过、不写入**。
- `alreadyConfigured`：缓存已有期望值，但原生/第三方/本工具来源不确定；**不重复写入**，不标记“原生”。
- `eligibleToEnable`：已验证型号+系统布局+目标硬件，当前值未开启；可推荐暂存，用户确认后才可写入。
- `unsupported`：缺少必要硬件或明确不支持；不可写。
- `unknown`：缺少机型、构建、布局、证据；默认只读，不推荐写入。
- `conflict`：依赖/互斥项或读取来源冲突；停止本组自动应用。

分类必须以**每项功能**独立计算，不能用“国行设备”整体标签代替硬件检测。原生支持 Apple Intelligence、Dynamic Island 等功能，全部自动排除对其 MG 字段的改动。已配置≠原生，已写入≠系统正在生效，系统读取支持≠网络服务可用。

## 历史修改的识别与证据等级
只读比对三源：A) app 已存历史操作记录/原值备份；B) 当前 CacheData/CacheExtra (含键类型、原本缺失状态、UUID、缓存布局)；C) 系统实时 MGCopyAnswer 可读取值。还可使用用户**主动导入且验签/校验成功**的独立设备备份。
输出：
1. `selfManaged`：匹配本 App 历史写入记录，展示“本软件修改”与时间；
2. `externallyChangedVerified`：有可信基线、现值有差异；显示“与已验证历史备份不同”，不擅自断言哪个第三方工具；
3. `suspiciousDifference`：存在与公开默认资料不同、读回矛盾等迹象，但证据不足；显示“疑似被改动”，不能宣称已确认；
4. `noEvidence`：无法确定是否改动；显示“未发现可证明的历史改动”，不声称“原厂”。

不能根据当前值或型号映射**凭空推出此前原值**；没有可信原值，就不能提供“一键恢复原厂”。

## 精准一键恢复
恢复中心按照“本应用有原值记录 / 导入可信快照 / 仅疑似改动无备份”分组。恢复前预览包含：字段、当前值、目标值、是否原本不存在、快照时间与来源、设备及系统身份匹配、将影响的关联项。默认只勾选符合全部前置条件者。
- 只恢复确有可信原值的字段；原本缺失则删除新增键，不填造默认值。
- 恢复前再备份当前状态；校验 SHA-256、CacheUUID/版本/长度、设备稳定身份和布局，防止跨设备或跨系统错误恢复。
- 校验失败/没有备份 → 禁用恢复，提示可导入旧备份或查看手动诊断，不提供猜测性“强制还原”。
- 写后读回校验，结果展示“恢复成功/部分失败/未操作”，保留可导出的脱敏日志。
- 恢复范围默认限于 LilaShift 记录的操作，不应顺带覆盖用户由其他工具做的独立改动。

## 国行不同型号智能预设
基于精确 ProductType + 芯片/硬件 + iOS build + 可访问缓存布局 + 实际权限 + 已验证实验矩阵，生成单机型建议计划。规则：原生项自动跳过，已配置项跳过，不支持/未知项禁用，依赖项同时满足方可暂存；互斥冲突不可自动选择。地区码与销售地区必须分离；eSIM 无 eUICC 硬件时不能承诺激活；AI 开关不代表 Apple 服务授予权限。#178/#266 争议项默认隔离，仅在证据充分时显示可选择实验项。

## 用户看得懂的功能卡与排序
主 Tab 顺序：首页 / 功能 / 检测 / 恢复与记录 / 我的。
首页顺序：设备概况 → 设备能力识别 → 备份健康 → 推荐操作 → 最近变更。
功能页分组：国行功能、AI/Siri、显示交互、相机声音、设备系统、iPad、个性化；高级实验隐藏在开发者区域。
每张卡显示：中文名、一句话用途、当前状态（原生支持/已配置/可尝试/不支持/未验证/冲突）、风险、需要重启与否。展开含：这是做什么、适用机型、开启后可能变化、依赖及互斥、作用底层配置、具体验证位置、如何恢复、依据与最后核验日期。原生项目默认折叠到“系统已支持，无需修改”。
示例：
- eSIM：“调整 eSIM 能力判断标记，不能凭空增加 eUICC 硬件；是否能开卡还取决于系统、运营商与地区。”
- Apple Intelligence：“调整设备能力标记，实际功能还取决于硬件、模型下载与 Apple 服务。”
- 地区代码：“改变 MG 地区能力判断，不等于修改 Apple ID、语言、定位或设备销售地区。”

## 执行与验收
0. 修复现有 P0：DevicePlistWriter O_NOFOLLOW 回退/文件身份；#178 冲突；首次备份不应被叫作原厂；未知机型前缀自动支持；来源许可证/署名。
1. 提取 `FeatureDescriptor` 版本化元数据及解释文本。每条映射 featureID、公开/混淆键、系统/硬件前提、证据、风险、依赖/互斥、恢复方案。
2. 实现只读 `FeatureEligibilityEvaluator` + `ChangeProvenanceDetector`，用稳定设备画像、缓存和现场读回计算状态，不产生写入副作用。
3. 实现 `SmartPlanBuilder` 纯函数：过滤原生/已配置项、拒绝未知与冲突、按依赖排序，并生成可预览的暂存计划。
4. 实现备份来源和恢复预览（先做只读 UI），后续接入经过故障注入测试的安全写入层。
5. 单元测试必须覆盖：原生支持而缓存被改、无备份疑似修改、旧系统 UUID、不同设备、缺少硬件、未知机型、#178 冲突、多功能重复写入、恢复缺失键与局部失败。
6. 真机按型号及 OS build 验证后再允许 Beta；不修改现有发布标签。
