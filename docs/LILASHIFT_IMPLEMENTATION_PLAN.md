# LilaShift（紫序）分阶段实施方案 / Implementation Plan

目标：将现有 **GestaltX v1.0.7 + LilaShift 补丁** 升级成有明确来源、可测试、可恢复的 iOS 设备配置与诊断工具。**不覆盖任何正式 Release / IPA**；只通过开发分支、草稿 PR、明确的版本标签发布。

## 0. 发布治理与分支

- 当前发布标签 `v1.0.7-china-unlock`：冻结，继续保留原 IPA 和对应源码包。
- 开发基线：当前 `main`（含尚未作为旧 IPA 发出的新版补丁），立即新建 `dev/*` 分支开发。
- 后续建议第一个新版本：`v1.1.0-beta.1`，展示品牌 **LilaShift / 紫序**；**只有 P0 风险解除后才允许真机测试构建进入 Release**。
- 源码仓库现在是 [fafa920q-hue/LilaShift](https://github.com/fafa920q-hue/LilaShift)；遗留 GitHub 链接更新应在新版本分支进行，不能让旧标签指向新构建输入。
- 每项功能 PR：变更清单、来源许可证、兼容性矩阵、离线测试、截图、失败恢复演练。合并需要明确评审。

## 1. P0 — 先收敛安全底座（必须先完成）

### P0.1 DevicePlistWriter 固化与测试

**现有**：`GestaltX/DevicePlistWriter.swift`，不清空 0 字节、读回、回滚。  
**下一步**：
1. 去掉 `O_NOFOLLOW` 失败后无条件无保护重试；增加已打开 fd 与预读目标的 inode、设备号、文件类型、权限和长度校验，保持 symlink 方案与沙盒访问兼容。
2. 对写入和回滚使用可故障注入的底层接口；增加部分写入、短写、读回失败、尾部截断、同步失败及回滚失败测试。
3. 明确失败时错误信息和保留备份策略；文案不得承诺断电绝对安全。

**验收**：离线测试中故障不可假报成功；失败时能够恢复或明确标注不可恢复；未经通过所有设备一致性检查不启动系统写入。

### P0.2 双重备份的真实含义

**现有**：`GestaltFileStore`、`SystemVaultTests.swift`。  
**下一步**：设计 `BackupProvenance` 数据模型，区分首次观察、可信来源、历史恢复、未知/校验失败；单独保存设备身份/系统版本/CacheUUID/Hash、生成时间、编辑前来源。先实现可验证备份导出和恢复前预览；“原厂”措辞必须由证据支持。

**验收**：损坏库、旧系统 UUID、不同设备、重签/卸载重装、缺失元数据、备份本身已被修改、离线恢复等测试全部通过；不自动覆盖有效的最早快照。

### P0.3 AI 与地区安全门控

**现有**：`AIReadinessCheckup.swift`、`DeviceAIEligibility.swift`、`USRegulatoryModelMapping.swift`。  
**下一步**：去掉未知机型宽前缀自动支持；将 AI 条件分为“配置已写入”“系统实时返回”“服务实际可用”三种不同层级。针对争议的 Audio Intelligence #178 和 Personal Translator #266 必须先做设备测试和可逆实验；任何不确定状态默认只读/禁用对应高风险操作。

**验收**：未知机型 fail-closed；原生 AI 与非原生 AI 各有设备矩阵，原始/写后/冷重启/恢复过程可追溯，绝不凭字段开关标记就宣布服务开通。

### P0.4 合规与构建身份

保留 **huamidev/GestaltX GPLv3**、**Kianuni/Erosion-CN GPLv3**、**jailbreakdotparty/Erosion GPLv3** 的可核对署名；**MGKeys MIT** 若引入数据/代码则附许可；**Nugget AGPLv3** 只研究设计，不直接复制代码。为每次新 IPA 保存固定上游 SHA、补丁 SHA256、Xcode 版本、完整修改源码、构建日志、二进制哈希。保留原版作者与衍生维护者的区分。

**验收**：双上游来源表可逐文件追踪；App 关于页、仓库说明和新 Release 一致；新版本有完整源码和 hash，旧版不动。

## 2. P1 — 三类高价值可见模块

| 模块 | 复用/新增 | 设计工作 | 最低验收 |
|---|---|---|---|
| 实时 MG 检测中心 | 扩展已存在的 `LiveGestaltProbe` | 三源同屏：原始备份 / 现存缓存 / `MGCopyAnswer`；支持关键字与槽位检查；导出脱敏报告；只读默认 | 无写操作；模拟器与失败返回 unknown；设备上 20+ 标准键值对照，界面不阻塞 |
| 智能兼容性诊断 | 扩展现有 AI 四要素卡 | 设备特征、OS build、App Group、可读取性、槽位解析、服务状态分别显示；每项给出验证依据 | 对未知版本准确报告“未验证”；无法读时不显示“已解锁” |
| 完整中文界面 | 利用 `Localizable.xcstrings` 和 `scripts/generate_localization.py` | 跟随系统 / 简中 / English 手动切换；保留原项目更多语种；文本回退/动态字体/无障碍 | 中英核心页面无英文漏出；长文本不截断；语言切换不丢未保存修改 |

## 3. P2 — 功能目录与个性化

**预设数据库**：将 `Capabilities.swift` 的说明逐步抽取为**版本化元数据**，字段包括 `id`、公开键名/混淆键名、平台、OS 最小/最大验证范围、硬件要求、风险等级（read-only/low/high）、默认开关、安全还原逻辑、证据出处。可从 **MGKeys MIT** 研究键名，但不得把未经核验的键直接放入可写列表。JSON/Swift 静态生成必须可离线使用，无动态远端推送写入能力。

**壁纸与个性化**：先审计上游现有 `CustomizationStore.swift`、`CustomizationFiles.swift`、`LaunchArtworkStore.swift`。按“导入 → 预览 → 修改清单 → 备份 → 应用 → 验证 → 恢复”统一 UI。强化 zip 路径穿越、总大小限制、symlink、文件类型、权限与失败恢复测试；不要直接复制 Erosion-CN 全部美化模块。

**验收**：所有已收录预设能产生稳定预览；每项写入都能撤销；恶意资源包无目录越界；壁纸功能在不获得系统写权限时优雅降级。

## 4. P3 — 诊断 + 应用数据工具（独立权限隔离）

| 模块 | 初始发布范围 | 后续范围 | 边界条件 |
|---|---|---|---|
| 电池与系统诊断 | 只读、电池概要、Crash/Jetsam 列表、可选脱敏导出 | 经确认后再加 Powerlog 安全读取 | 无权限时禁用；不修改 Powerlog、系统数据库 |
| 应用存档 | 默认只读发现；用户指定单个 App 的手动导出；支持恢复预览 | 经测试后做逐 App 恢复及 ZIP 导入 | 严格 Bundle ID/容器 UUID 校验、备份先行；未经授权不碰其他 App 数据 |
| 缓存管理 | 先统计**本 App 自有** Caches/tmp，生成报告并让用户确认 | 再评估用户授权的其他容器 | 不提供“系统级一键清空”；排除 Documents、数据库、账号、系统及聊天数据；回滚不可逆的删除动作不应声称安全 |

所有跨容器数据操作必须检查 App Group / 沙盒授权；不得默认具有读取或修改其他 App 私有内容的能力。

## 5. 测试和发布门禁（按序推进）

1. **Linux 静态检查**：固定上游 SHA，`git apply --check`；检查合规文件与构建输入，单独审查二进制补丁和外部素材来源。
2. **macOS 单元测试**：现有 `DocumentTests`、`CacheLayoutGatingTests`、`DevicePlistWriterTests`、`SystemVaultTests`、`AIReadinessTests`、本地化测试；故障注入作为新增必测项目。
3. **Xcode 模拟器**：编译 Debug/Release 与分享扩展；测试 UI、手动中英文切换、导入/导出和无权限退化；不模拟真实的 MobileGestalt 生效结论。
4. **真实设备小范围测试**：分型号及 iOS build；初次启动、普通读取、功能暂存、应用、冷重启、读回、恢复、卸载重装及权限变化；测试前独立完整备份。
5. **法律和供应链检查**：版权、第三方资源、许可证、使用限制、依赖来源与打包文件清单。
6. **发布**：新版本 `v1.1.0-beta.1`，新 IPA + 完整对应源码、SHA256SUMS、完整 Release Notes；绝不覆盖 `v1.0.7-china-unlock`。
