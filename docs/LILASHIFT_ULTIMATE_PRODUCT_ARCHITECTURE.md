# LilaShift Ultimate（紫序）——产品与工程蓝图
> 2026-11-13 · 设计/开发中，不代表已实现、已验证或已发布。本分支不改 main、正式 tag 和 IPA。
> 设计目标：对可证明的设备状态作出准确解释与安全操作；不声称“全机型通用”“100% 不白苹果”“破解 Apple 服务权限”。

## 产品定位
“读得懂、判断准、改得稳、退得回、装得上”：融合 GestaltX 的 MG 设备操作、Erosion-CN 的诊断与个性化思路、MGKeys 的键名索引思路、Nugget 的流程组织思路、Feather/SideStore 的安装体验（**先核查许可证、不得直接拼接各项目源码**）。差异化不是项目数量而是可验证的安全能力、数据溯源与清楚的中文说明。

## 一级导航（固定）
1. **首页**：设备画像、系统能力概况、备份健康、推荐动作、最近变更。禁止假进度/虚构检测结果。
2. **功能**：国行适配、AI/Siri、通信/eSIM、显示交互、设备与相机、iPad、壁纸个性化；先进设置收纳“实验室”。
3. **检测**：MG 三源对比、兼容性/权限/签名/App Group、系统、电池、崩溃日志，默认只读。
4. **恢复**：历史变更、原值证据、逐项及批量恢复、备份导入导出、脱敏报告。
5. **我的**：安装与签名、语言、关于/贡献者/许可证、版本验证、帮助与反馈。

## 每张功能卡统一的数据模式
id、中文名、英文名、一句话解释、详细工作原理、实际影响、所需硬件、精确型号、系统 build 适用范围、缓存类型与布局、默认值证据、依赖、互斥、风险、预期生效方式（即时/重启/联网/不可证实）、验证方法、恢复条件、上游来源/许可证、证据日期。
核心分类：`nativeSupported` / `alreadyConfigured` / `eligibleToEnable` / `unsupported` / `unknown` / `conflict`。**原生支持和已满足期望值不改写；未知或冲突仅展示解释，不自动写入。** 不要把“字段已写入”当成“服务已激活”。

## Smart Engine 六层
- `DeviceProfiler`：只读机型/系统 build/硬件能力/签名权限/可读 MG；未知机型严格 fail-closed。
- `CapabilityCatalog`：带来源证据和版本化适配规则的离线功能数据库，不开放远端任意下发写入键。
- `EligibilityEvaluator`：单功能三态加风险/冲突分类；对“原生”的判断必须有硬件与官方/真机证据。
- `ChangeProvenance`：对比本应用历史记录、可信早期快照、当前缓存、实时 MG；无基线仅报“疑似/未知”，不可推定原厂值。
- `SmartPlanBuilder`：去重、排序依赖、自动过滤原生与已配置、检查互斥/危险组合、生成可审阅变更清单。
- `SafeTransaction`：原值预备份、设备/缓存 UUID 匹配、fd 身份验证、写回/校验/失败状态分级与精准恢复。不能承诺断电绝对原子。

## 极致交互标准
- 新手模式：用户看到“它是做什么/适用谁/有什么风险/如何恢复”；专家模式才显示 MG 原始键名与槽位。
- 所有状态都有来源：“来自硬件/系统实时读取/本应用记录/导入快照/公开参考”，无法证明则标记“未验证”。
- 首页智能推荐仅呈现安全合规且设备匹配的可选动作；禁止自动替用户执行系统改写。
- 每张功能卡的“更多”包括底层键、依赖图、验证步骤、最近核验日期、恢复演练。危险项二次确认。
- 视觉：苹果原生银白+淡紫玻璃、系统字体与动态类型；系统深色模式/减少透明度/VoiceOver 友好；完整简中/英文。
- 检测中心统一按设备/功能/来源过滤；显示测量时间、只读/写入权限、实际成功/未知/不可用。

## 签名与安装不是一个不受限制的“免费自签按钮”
- A 免费 Apple ID：桌面本地助手协助签名、首次安装与续签；账号双重认证在受信任流程中完成，不向紫序服务器收集密码。遵循苹果账号使用和设备数量限制。
- B 自带证书：iPhone 本地导入 P12 + 密码 + mobileprovision，预检合法性、有效期、Team ID、Bundle ID、Entitlements、扩展 App Group；禁止日志记录或上传私钥。
- C 已有工具：引导用户经 AltStore/SideStore/LiveContainer 兼容安装，附诊断，不承诺容器权限/分享扩展必然相同。
- D 开发调试：开发者工具链管理 profile/证书后签名，按支持的平台操作。
- **不可能依赖尚未安装的 LilaShift 在同一台未授权设备上完成自己的首次安装。** 需要外部首次安装步骤。自签不消除 iOS 权限限制。
- 只能在受支持签名流程成功后启动运行时权限检查；App Group 主 App + 分享扩展必须共同具备授权，否则显示“不兼容/部分功能不可用”。

## 依次交付的阶段
1. **S0 安全基础**：P0 修复、原值/来源模型、离线故障注入、构建可复现与版权合规。
2. **S1 智能识别**：逐功能适配规则、原生过滤、已有修改证明级别、只读 MG 三源视图。
3. **S2 安全事务与恢复**：计划预览、依赖/互斥、预备份、写入后校验、历史恢复。
4. **S3 安装与自签**：安装方式向导 + IPA 签名预检；桌面本地 Apple ID 签名辅助与 iOS 持证本地签名分别开发，不触碰用户密码服务器化。
5. **S4 系统工具**：壁纸、能耗、Crash、应用数据只读诊断；跨容器与删除功能须单独权限、安全和恢复评审。
6. **S5 设计与发布**：无障碍、易读本地化、UX 研究、真实机型矩阵、签名与安装真机测试、源码及二进制校验、新 Beta tag。

## 工程门禁
每个 PR 有：威胁模型、许可证归属、真机适配清单、自动测试、手工测试记录和回滚方案。GitHub CI 绿灯≠真机写入成功；本地静态预检≠可信签名；没有现场设备样本/正式证书不宣称可安装。
